# 文档检查表

[English](docs-checklist.md)

1. 一篇文档服务一类读者、解决一个问题。操作进指南，精确契约进参考，宿主维护进贡献者路径。
2. 用当前代码、测试和示例核实事实，使用真实 UI 名称。标明实验性功能，区分 dev 与已发行版本。
3. 说明准备条件、完整步骤、预期结果与下一步。优先使用一个连续示例。
4. 链接权威定义，不重复解释。迁移时保留有用的旧路径与锚点。使用大小写准确的仓库相对链接，不引用本机忽略产物。
5. 中英文事实一致。英文用 `.md`，中文用 `.zh-CN.md`；底层参考不必全译，但两种语言都应有连续的用户和开发者入门路径。
6. 在 `mkdocs.yml` 与 `frontend/src/shell/documentation.ts` 中登记到同一读者分类，运行[文档检查](../developers/documentation.md)。

正式说明不放某日测试数、PR 总结、迁移流水账或未来路线图。只有仍有价值的历史依据保存在 `docs/internal/` 并标为非权威；其余通过 Git 历史追溯。
